# PMS — Project Management System (PHP + MySQL, XAMPP)

## التشغيل على XAMPP (Setup)

1. **انسخ المجلد**
   انسخ مجلد `pms` بالكامل إلى: `C:\xampp\htdocs\pms` (ويندوز) أو `/Applications/XAMPP/htdocs/pms` (ماك).

2. **شغّل Apache و MySQL**
   افتح XAMPP Control Panel وشغّل خدمتي Apache و MySQL.

3. **استورد قاعدة البيانات**
   افتح `http://localhost/phpmyadmin` → أنشئ تبويب SQL جديد → استورد ملف
   `database/schema.sql` (أو الصقه وشغّله). هذا ينشئ قاعدة البيانات `pms_db` وكل الجداول.

3.5. **استورد التحديثات (Migrations)** — إن كانت هذه أول مرة تُنزّل فيها النظام، نفّذ الملفين التاليين بالترتيب من نفس تبويب SQL في phpMyAdmin (بعد schema.sql مباشرة):
   - `database/migrations/001_permissions.sql` — نظام الصلاحيات التفصيلية
   - `database/migrations/002_notifications.sql` — نظام الإشعارات

   إن كنت تُحدّث نسخة موجودة سبق وشغّلت عليها schema.sql فقط، شغّل الملفين أعلاه فقط
   (لا تُعد استيراد schema.sql — بياناتك الحالية ستبقى كما هي).

4. **تحقق من إعدادات الاتصال**
   الإعداد الافتراضي يعمل مباشرة مع XAMPP (`root` بدون كلمة مرور) — لا حاجة لأي تعديل محليًا.
   لو تريد نقل النظام لاستضافة حقيقية لاحقًا، انسخ `.env.example` إلى `.env` وعدّل القيم هناك
   بدل تعديل الكود مباشرة (راجع قسم "الجاهزية للإنتاج" أسفل الصفحة).

5. **أنشئ حساب الأدمن**
   افتح المتصفح على: `http://localhost/pms/install.php`
   واملأ الاسم/البريد/كلمة المرور. هذا ينشئ حسابك كأدمن + مشروع تجريبي جاهز.
   بعد الإنشاء، يُفضّل حذف أو إعادة تسمية `install.php` (يمنع نفسه من العمل مرة ثانية تلقائيًا،
   لكن حذفه أنظف).

6. **سجّل الدخول**
   `http://localhost/pms/modules/auth/login.php`

## هيكل المشروع

```
pms/
├── .env.example      قالب متغيرات البيئة (انسخه إلى .env عند النشر — لا يُرفع لـ Git)
├── config/
│   ├── env.php        محمّل بيئة بسيط بدون Composer
│   ├── database.php    اتصال PDO (يقرأ من .env إن وُجد)
│   └── app.php         bootstrap: أخطاء، جلسة، صلاحيات، تحميل كل شيء
├── includes/
│   ├── repositories/   طبقة Repository (المرحلة 4): كل استعلامات SQL معزولة هنا
│   ├── helpers.php     دوال عامة (لم تعد تلمس SQL مباشرة)
│   └── auth.php        مصادقة + userCan()/requirePermission() (المرحلة 5)
├── modules/
│   ├── auth/          تسجيل الدخول والخروج
│   ├── dashboard/     لوحة التحكم الرئيسية
│   ├── projects/      مشاريع: قائمة، إضافة/تعديل، عرض تفصيلي، مرفقات، حذف ناعم
│   ├── tasks/         مهام وفرعيات: تعليقات، مرفقات، تبعيات، My Tasks، حذف ناعم
│   ├── team/          أعضاء الفريق: إضافة/تعديل/حذف مع ضمانات أمان
│   ├── reports/        Gantt، Burndown، أداء الفريق (+تصدير CSV)
│   ├── attachments/    تنزيل آمن للملفات المرفوعة
│   ├── notifications/  قائمة الإشعارات + تحديد كمقروء (المرحلة 6)
│   └── settings/       شاشة إدارة الصلاحيات (المرحلة 5)
├── assets/css/        نظام التصميم (style.css)
├── uploads/           ملفات المرفقات (محمية بـ .htaccess من تنفيذ PHP والفهرسة)
├── storage/
│   ├── logs/           سجل أخطاء PHP (بدل عرضها للمستخدم في وضع production)
│   └── backups/        نسخ احتياطية من قاعدة البيانات (تُنشأ تلقائيًا بواسطة scripts/backup.sh)
├── scripts/backup.sh  سكربت نسخ احتياطي (mysqldump + تدوير تلقائي)
├── database/
│   ├── schema.sql       المخطط الأساسي الكامل
│   └── migrations/      تحديثات تراكمية على قاعدة بيانات موجودة (001، 002، ...)
└── install.php        معالج الإعداد لمرة واحدة
```

## الميزات المُنجزة حسب المرحلة

**المرحلة 1 — الأساس:** مصادقة، صلاحيات (admin/manager/member)، CRUD كامل للمشاريع/المهام/الفريق، لوحة تحكم، سجل نشاط.

**المرحلة 2 — إغلاق الفجوات الوظيفية:**
- رفع/تنزيل المرفقات على مستوى المشروع والمهمة (whitelist امتدادات + حد 15 ميجا + تخزين خارج نطاق تنفيذ PHP)
- تبعيات المهام (Depends On) مع تحذير بصري عند وجود تبعية غير مكتملة
- حذف ناعم فعلي (Soft Delete) لكل من المشاريع/المهام/أعضاء الفريق، مع ضمانات: لا يمكن حذف آخر أدمن، لا يمكن حذف نفسك
- صفحة "My Tasks" لعرض مهام المستخدم الحالي فقط
- حقل `actual_hours` مفعّل في نموذج المهمة

**المرحلة 3 — التقارير والتحليلات:**
- مخطط Gantt (خط زمني للمهام حسب الحالة، بدون مكتبات خارجية)
- Burndown Chart (SVG مُولّد من PHP: المتبقي الفعلي مقابل الوتيرة المثالية)
- تقرير أداء الفريق: معدل الإنجاز، المهام المتأخرة، متوسط الساعات المقدّرة/الفعلية
- تصدير CSV لتقرير أداء الفريق (بدون الحاجة لمكتبات خارجية عبر Composer)

**ملاحظة:** تصدير PDF/Excel (البند 3.4 الأصلي) يحتاج مكتبة خارجية عبر Composer
(مثل TCPDF أو PhpSpreadsheet) — لم يُنفَّذ بعد لإبقاء المشروع بدون تبعيات خارجية؛
تم تعويضه بتصدير CSV الذي يفتح مباشرة في Excel.

**المرحلة 4 — إعادة الهيكلة (Repository Pattern):**
- كل استعلامات SQL انتقلت من داخل ملفات `modules/*` إلى 5 كلاسات Repository:
  `ProjectRepository`, `TaskRepository`, `UserRepository`, `ActivityRepository`, `AttachmentRepository`
- ملفات `modules/*` أصبحت "رفيعة" (thin controllers): تستدعي دوال Repository بأسماء واضحة
  (`$taskRepo->forProject($id)`) بدل كتابة SQL خام في كل صفحة
- `logActivity()` و `attemptLogin()` تستخدمان الـ Repositories داخليًا الآن أيضًا
- لا تغيير في السلوك الوظيفي للمستخدم — هذه المرحلة صيانة داخلية بحتة

**المرحلة 5 — الصلاحيات التفصيلية:**
- جدولا `permissions` (كتالوج الصلاحيات) و `role_permissions` (مصفوفة دور × صلاحية)
- `PermissionRepository` مع تخزين مؤقت (cache) على مستوى الطلب الواحد
- دالتان جديدتان في `includes/auth.php`: `userCan('key')` و `requirePermission('key')`
- الأدمن دائمًا صاحب صلاحية كاملة تلقائيًا (fail-safe)، بينما Manager وMember قابلان للتخصيص
- شاشة إدارية `modules/settings/permissions.php` (تظهر فقط لمن يملك `settings.manage`) لتفعيل/تعطيل
  كل صلاحية عبر جدول Checkboxes، بدون لمس الكود
- كل أزرار الحذف/الإضافة في الواجهات (مشاريع، مهام، فريق) تُخفى تلقائيًا حسب صلاحيات المستخدم الحالي
- **صلاحيات القيم الافتراضية** مطابقة تمامًا للسلوك القديم المبني على الأدوار الثابتة — لا شيء يتغيّر
  لأي مستخدم حتى تُعدّل المصفوفة بنفسك من شاشة الإعدادات

**المرحلة 6 — الإشعارات الداخلية:**
- جدول `notifications` (مستلم، مُرسِل، نوع، رسالة، رابط، حالة القراءة)
- `NotificationRepository`: إنشاء، عدّ غير المقروء، سرد، تحديد كمقروء (فردي/الكل)
- جرس إشعارات 🔔 في الشريط العلوي مع عدّاد أحمر للرسائل غير المقروءة، يظهر في كل الصفحات
- صفحة `modules/notifications/index.php` لعرض كل الإشعارات + زر "تحديد الكل كمقروء"
- إشعارات تلقائية تُطلق فعليًا عند:
  - تعيين مهمة لعضو (أو إعادة تعيينها لعضو مختلف)
  - إضافة تعليق على مهمة من شخص غير المُعيَّن لها
- (لم يُنفَّذ بعد: تنبيهات اقتراب موعد الاستحقاق — تحتاج مُجدوِل Cron يفحص المهام دوريًا؛ البنية التحتية
  (جدول notifications) جاهزة لإضافتها بسهولة لاحقًا)

**المرحلة 7 — الجاهزية للإنتاج:**
- `.env.example` + `config/env.php`: محمّل متغيرات بيئة بسيط بدون أي حزمة خارجية (بدون Composer)؛
  انسخ `.env.example` إلى `.env` وعدّل القيم عند النشر على استضافة حقيقية — الكود يبقى كما هو
- `config/database.php` يقرأ `DB_HOST/DB_NAME/DB_USER/DB_PASS` من `.env` إن وُجد، ويرجع تلقائيًا
  لإعدادات XAMPP الافتراضية إن لم يوجد — تطوير محلي بدون أي إعداد إضافي
- تشديد أمان الجلسة: `httponly`، `SameSite=Lax`، و `Secure` تلقائيًا عند `FORCE_HTTPS=1` في `.env`
- تسجيل أخطاء PHP إلى `storage/logs/error.log` بدل عرضها للزائر مباشرة عند `APP_ENV=production`
  (تبقى تظهر على الشاشة في `APP_ENV=local` لتسهيل التطوير)
- `storage/` محمي بالكامل من الوصول المباشر عبر المتصفح (`.htaccess`)
- `scripts/backup.sh`: نسخ احتياطي تلقائي لقاعدة البيانات عبر `mysqldump` مع ضغط `gzip` وتدوير
  تلقائي (يحتفظ بآخر 14 نسخة فقط) — جاهز للجدولة عبر `cron` (التعليمات داخل الملف نفسه)
- `.gitignore` يستثني `.env`، الملفات المرفوعة، السجلات، والنسخ الاحتياطية من أي نظام تحكم بالإصدارات
