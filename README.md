# PMS — Project Management System

نظام متكامل لإدارة المشاريع والمهام وأعضاء الفريق، مبني باستخدام **PHP + MySQL** ومهيأ للعمل بسهولة على **XAMPP**، مع بنية قابلة للتوسع والتهيئة للنشر في بيئة الإنتاج.

## 🚀 التشغيل على XAMPP

### 1. نسخ المشروع

انسخ مجلد `pms` بالكامل إلى مجلد `htdocs` الخاص بـ XAMPP:

**Windows**

```text
C:\xampp\htdocs\pms
```

**macOS**

```text
/Applications/XAMPP/htdocs/pms
```

### 2. تشغيل Apache وMySQL

افتح **XAMPP Control Panel**، ثم شغّل:

* Apache
* MySQL

### 3. إنشاء قاعدة البيانات

افتح **phpMyAdmin** من خلال:

```text
http://localhost/phpmyadmin
```

ثم:

1. افتح تبويب **SQL**.
2. افتح الملف:

   ```text
   database/schema.sql
   ```
3. الصق محتواه في محرر SQL وشغّله.

سيؤدي ذلك إلى إنشاء قاعدة البيانات:

```text
pms_db
```

مع جميع الجداول الأساسية المطلوبة للنظام.

### 4. تشغيل Migrations

إذا كانت هذه **أول مرة** يتم فيها تثبيت النظام، نفّذ ملفات الـ Migrations التالية **بالترتيب** بعد تشغيل `schema.sql`:

```text
database/migrations/001_permissions.sql
database/migrations/002_notifications.sql
```

#### عند تحديث نسخة موجودة

إذا كان لديك نظام قائم سبق تشغيل `schema.sql` عليه، **لا تقم بإعادة استيراد `schema.sql`** حتى لا تتأثر البيانات الحالية.

شغّل فقط:

```text
001_permissions.sql
002_notifications.sql
```

من خلال تبويب **SQL** في phpMyAdmin.

### 5. إعداد الاتصال بقاعدة البيانات

يعمل النظام افتراضيًا مباشرة مع إعدادات XAMPP الشائعة:

```text
DB_HOST=localhost
DB_NAME=pms_db
DB_USER=root
DB_PASS=
```

لذلك لا تحتاج إلى إجراء أي تعديل محلي في الإعدادات.

عند نقل النظام إلى استضافة حقيقية، يُفضّل نسخ:

```text
.env.example
```

إلى:

```text
.env
```

ثم تعديل قيم الاتصال والإعدادات داخل `.env` بدلًا من تعديل الكود مباشرة.

> **مهم:** لا تقم برفع ملف `.env` إلى Git.

### 6. إنشاء حساب المدير

افتح:

```text
http://localhost/pms/install.php
```

ثم أدخل:

* الاسم
* البريد الإلكتروني
* كلمة المرور

سيقوم معالج التثبيت بإنشاء حساب **Administrator** وإنشاء مشروع تجريبي جاهز للاستخدام.

بعد اكتمال التثبيت، يُنصح بحذف أو إعادة تسمية:

```text
install.php
```

النظام يمنع إعادة تشغيل المعالج بعد اكتمال الإعداد، لكن حذف الملف يُعد ممارسة أمنية وتنظيمية أفضل.

### 7. تسجيل الدخول

بعد إنشاء الحساب، انتقل إلى:

```text
http://localhost/pms/modules/auth/login.php
```

# ✨ الميزات المنجزة

* نظام مصادقة وتسجيل دخول.
* ثلاثة أدوار رئيسية:

  * Administrator
  * Manager
  * Member

* إدارة كاملة للمهام **CRUD**.
* إدارة أعضاء الفريق.
* لوحة تحكم رئيسية.
* سجل للنشاطات.

---

## المرحلة 2 — استكمال الوظائف الأساسية

تم إغلاق الفجوات الوظيفية وإضافة:

### 📎 المرفقات

* رفع المرفقات على مستوى المشروع والمهمة.
* قائمة امتدادات مسموحة.
* الحد الأقصى لحجم الملف: **15 MB**.
* تخزين الملفات بطريقة تمنع تنفيذ PHP عليها.

### 🔗 تبعيات المهام

دعم علاقات:

```text
Depends On
```

مع إظهار تحذير مرئي عندما تكون هناك مهمة تعتمد على مهمة لم تكتمل بعد.

### 🗑️ الحذف الناعم

تم تطبيق **Soft Delete** على:

* المشاريع.
* المهام.
* أعضاء الفريق.

مع ضمانات أمنية، منها:

* منع حذف آخر Administrator.
* منع المستخدم من حذف حسابه بنفسه.

### 👤 My Tasks

صفحة مخصصة لعرض المهام المسندة إلى المستخدم الحالي فقط.

### ⏱️ الساعات الفعلية

تم تفعيل الحقل:

```text
actual_hours
```

ضمن نموذج المهمة لتسجيل الوقت الفعلي المستغرق.

# 📊 المرحلة 3 — التقارير والتحليلات

### Gantt Chart

مخطط زمني للمهام حسب حالتها، تم تنفيذه بدون الاعتماد على مكتبات خارجية.

### Burndown Chart

مخطط **Burndown** يتم توليده باستخدام SVG من PHP، ويعرض:

* المتبقي الفعلي.
* الوتيرة المثالية للإنجاز.

### تقرير أداء الفريق

يعرض مؤشرات تشمل:

* معدل الإنجاز.
* عدد المهام المتأخرة.
* متوسط الساعات المقدرة.
* متوسط الساعات الفعلية.

### تصدير CSV

يمكن تصدير تقرير أداء الفريق بصيغة:

```text
CSV
```

ويمكن فتح الملف مباشرة باستخدام Excel، دون الحاجة إلى Composer أو مكتبات إضافية.

> **ملاحظة:** تصدير PDF وExcel الأصلي يحتاج إلى مكتبات خارجية مثل `TCPDF` أو `PhpSpreadsheet`. لم يتم تضمينها للحفاظ على النظام خاليًا من التبعيات الخارجية، وتم توفير CSV كبديل عملي وخفيف.

# 🏗️ المرحلة 4 — إعادة الهيكلة باستخدام Repository Pattern

تمت إعادة تنظيم طبقة الوصول إلى البيانات بحيث أصبحت استعلامات SQL معزولة داخل Repositories متخصصة:

```text
ProjectRepository
TaskRepository
UserRepository
ActivityRepository
AttachmentRepository
```

وبالتالي أصبحت ملفات `modules/*` أقرب إلى **Thin Controllers**، بحيث تستدعي وظائف واضحة مثل:

```php
$taskRepo->forProject($id)
```

بدلًا من كتابة استعلامات SQL مباشرة داخل كل صفحة.

كما تم تحديث:

```text
logActivity()
attemptLogin()
```

لاستخدام طبقة الـ Repository داخليًا.

> هذه المرحلة عبارة عن إعادة هيكلة داخلية ولم تُغيّر السلوك الوظيفي للنظام بالنسبة للمستخدم النهائي.

# 🔐 المرحلة 5 — نظام الصلاحيات التفصيلية

تم تطوير نظام صلاحيات مرن بدل الاعتماد فقط على الأدوار الثابتة.

### مكونات النظام

تمت إضافة جدولين رئيسيين:

```text
permissions
role_permissions
```

حيث يمثل الأول كتالوج الصلاحيات، بينما يحدد الثاني الصلاحيات الممنوحة لكل دور.

### PermissionRepository

تم إنشاء:

```text
PermissionRepository
```

مع استخدام Cache على مستوى الطلب الواحد لتحسين الأداء.

### دوال التحقق من الصلاحيات

تمت إضافة:

```php
userCan('key')
requirePermission('key')
```

### صلاحيات Administrator

يمتلك Administrator جميع الصلاحيات تلقائيًا وفق مبدأ **Fail-Safe**.

أما Manager وMember فيمكن تخصيص صلاحياتهما.

### لوحة إدارة الصلاحيات

يمكن للإداري المخوّل الوصول إلى:

```text
modules/settings/permissions.php
```

وإدارة الصلاحيات باستخدام واجهة Checkboxes، دون الحاجة إلى تعديل الكود.

### التحكم في الواجهات

يتم إخفاء أزرار مثل:

* إضافة مشروع.
* حذف مشروع.
* إضافة مهمة.
* حذف مهمة.
* إدارة أعضاء الفريق.

تلقائيًا وفق صلاحيات المستخدم الحالي.

> الإعدادات الافتراضية للصلاحيات تحافظ على نفس السلوك السابق القائم على الأدوار. لذلك لن يتغير سلوك المستخدمين الحاليين ما لم يتم تعديل مصفوفة الصلاحيات يدويًا.

# 🔔 المرحلة 6 — نظام الإشعارات الداخلية

تمت إضافة نظام إشعارات داخلي متكامل.

### جدول Notifications

يتضمن معلومات مثل:

* المستلم.
* المُرسل.
* نوع الإشعار.
* الرسالة.
* الرابط المرتبط.
* حالة القراءة.

### NotificationRepository

يدعم:

* إنشاء الإشعارات.
* حساب عدد الإشعارات غير المقروءة.
* عرض الإشعارات.
* تحديد إشعار كمقروء.
* تحديد جميع الإشعارات كمقروءة.

### 🔔 جرس الإشعارات

تمت إضافة جرس إشعارات في الشريط العلوي مع عداد أحمر للإشعارات غير المقروءة، ويظهر عبر صفحات النظام.

### صفحة الإشعارات

يمكن الوصول إليها من:

```text
modules/notifications/index.php
```

وتتيح:

* استعراض جميع الإشعارات.
* تحديد جميع الإشعارات كمقروءة.

### الإشعارات التلقائية الحالية

يتم إنشاء إشعار تلقائي عند:

1. إسناد مهمة إلى عضو.
2. إعادة إسناد المهمة إلى عضو آخر.
3. إضافة تعليق على مهمة بواسطة شخص غير العضو المعيّن لها.

### التطوير المستقبلي

لم يتم بعد تنفيذ تنبيهات اقتراب موعد الاستحقاق؛ لأنها تتطلب **Cron Job** لفحص المهام دوريًا.

ومع ذلك، فإن البنية الحالية لنظام الإشعارات جاهزة لإضافة هذه الوظيفة مستقبلًا دون الحاجة إلى إعادة بناء النظام.

# 🚀 المرحلة 7 — الجاهزية للإنتاج

تم تجهيز النظام ليكون قابلًا للنقل من بيئة XAMPP المحلية إلى بيئة استضافة حقيقية.

### متغيرات البيئة

تمت إضافة:

```text
.env.example
config/env.php
```

ويعمل محمّل متغيرات البيئة بدون Composer أو أي حزمة خارجية.

عند النشر:

```text
.env.example → .env
```

ثم يتم تعديل الإعدادات وفق بيئة الخادم.

### إعدادات قاعدة البيانات

يقرأ:

```text
DB_HOST
DB_NAME
DB_USER
DB_PASS
```

من `.env` عند توفره، ويعود تلقائيًا إلى إعدادات XAMPP الافتراضية عند عدم وجوده.

وهذا يجعل التشغيل المحلي ممكنًا دون إعدادات إضافية.

### تشديد أمان الجلسات

تم تطبيق إعدادات أمنية للجلسات تشمل:

* `HttpOnly`
* `SameSite=Lax`
* `Secure` تلقائيًا عند تفعيل:

  ```text
  FORCE_HTTPS=1
  ```

### تسجيل الأخطاء

في بيئة الإنتاج:

```text
APP_ENV=production
```

يتم تسجيل أخطاء PHP في:

```text
storage/logs/error.log
```

بدل عرض التفاصيل للمستخدم.

أما في بيئة التطوير:

```text
APP_ENV=local
```

فتبقى الأخطاء ظاهرة لتسهيل عملية التطوير والتصحيح.

### حماية Storage

تمت حماية مجلد:

```text
storage/
```

من الوصول المباشر عبر المتصفح باستخدام `.htaccess`.

### النسخ الاحتياطي

يتوفر:

```text
scripts/backup.sh
```

لإنشاء نسخ احتياطية تلقائية لقاعدة البيانات باستخدام:

```text
mysqldump
```

مع:

* ضغط باستخدام `gzip`.
* تدوير تلقائي للنسخ.
* الاحتفاظ بآخر **14 نسخة** فقط.
* إمكانية جدولة التشغيل باستخدام **Cron**.

وتوجد تعليمات الجدولة داخل السكربت نفسه.

### حماية Git

يستثني `.gitignore` الملفات الحساسة وغير المناسبة للإيداع في Git، بما في ذلك:

```text
.env
uploads/
storage/logs/
storage/backups/
```

## 📝 ملاحظات مهمة للمطورين

* المشروع يعمل بدون Composer أو مكتبات PHP خارجية في وضعه الحالي.
* يُفضّل استخدام `.env` عند النشر على خادم حقيقي.
* لا ترفع `.env` أو ملفات الرفع أو السجلات أو النسخ الاحتياطية إلى Git.
* لا تعِد استيراد `schema.sql` عند تحديث قاعدة بيانات تحتوي على بيانات فعلية.
* عند تحديث النظام، نفّذ ملفات الـ Migrations الجديدة بالترتيب.
* احذف أو أعد تسمية `install.php` بعد الانتهاء من التثبيت.
* قبل النشر الفعلي، تأكد من تفعيل HTTPS وإعداد النسخ الاحتياطي المجدول.
